DanskPath — Simple Roadmap
Every Possible Case

Before fixing path bug — this doc shows every step a user can take, in every possible case. Guest-first per spec: Open→Understand→Assessment→Results→Strengths→Path→Preview→Start Learning→Create Account→Transfer→Dashboard→Exercise→Progress→Next. No dead ends.

🌍 Core Principle — Guest-First Per Spec

Open→ Understand→ Assessment→ Results→ Strengths→ Weaknesses→ Path Preview→ Decide→ Create Account→ Transfer→ Dashboard→ Exercise→ Progress→ Next
Landing extremely simple per spec: only logo/name, short headline, one-sentence explanation, primary CTA Take the Test, secondary Already have account? Log in, discreet Admin access, no long marketing/feature grids/competing CTAs. Assessment intro must explain what measures/duration/what learner receives after. Assessment one question at a time with progress Question X of Y + progress bar. Results must immediately provide useful info level + section scores + strengths separately from focus areas, avoid negative language. No dead ends every screen clear next action. Persistence guest data transferable no loss on close/refresh/logout.
